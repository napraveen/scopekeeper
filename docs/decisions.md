# Architectural & Design Decisions

## 1. Why Clerk is a Custom Agent Service Over the Switch Agent Protocol

While Scout (OpenCode), the Estimator (Claude Code), and the Builder (Codex) run as Console-managed coding agents inside Switch Console, Clerk is built as a standalone Python FastAPI service connected directly to Switch via the Switch Agent Protocol (`GET /agents/{agent_id}/connection/ws` and `POST /agents/{agent_id}/ops/{operation}`). A contract-and-ledger engine requires deterministic decimal pricing, transactional database persistence, optimistic concurrency control, scheduled timezone handovers (the evening and morning Flips), idempotent event deduplication (`processed_events`), and an HTTP/SSE surface for the agency dashboard. Running Clerk as a custom agent gives us strict state machines, audit-grade ledger rows linked to chat messages, and an independent 2-second WebSocket `ping`/`pong` loop that never stalls during LLM calls.

## 2. Why Room Membership Beats System Prompt Instructions for Confidentiality

Prompt instructions can be misunderstood or jailbroken; room membership is enforced by Switch Core at the transport boundary. Clerk is only a member of `acme-intake`, `acme-delivery`, and `acme-cr-NNN` change rooms—it is **never** added to `acme-client`, and `SwitchProtocolAdapter` (as well as `InMemorySwitch`) raises a `PermissionError` in code if any caller attempts to place a session or post a message as Clerk into `acme-client`. Conversely, Scout is only a member of `acme-client` and `acme-intake`, and rate cards (`rate-card.yaml`), envelopes (`envelope.yaml`), and internal margin discussions are attached only to `acme-delivery` and `acme-cr-NNN`. Even if a client asks Scout for hourly rates or internal contingency buffers, Scout literally has no access to those rooms or documents.

## 3. Why Money, Hours, and Dates are Deterministic in Code

Agencies cannot afford hallucinated quotes or shifting milestone dates. All pricing in ScopeKeeper uses Python's `decimal.Decimal` with `ROUND_HALF_UP` to the nearest `round_to` ($10) according to the exact formula $\text{price} = \operatorname{round}_{10}(h \times r \times (1 + c))$, and all schedule shifts use `round_half_up(hours / capacity_hours_per_week * 7)` calendar days with `zoneinfo` (`Asia/Kolkata` and `America/New_York`). The LLM is restricted to classifying requests against structured scope clauses and drafting short client wording from a `facts` JSON object. Before any LLM-generated wording reaches `acme-intake`, `domain/numbers_check.py` extracts every number, currency amount, and date token and verifies that each appears in `facts`; if any mismatch occurs after one retry, Clerk falls back to the deterministic template in `domain/templates.py`.

## 4. How Switch Agent-Only Room Roles and Human Governance Responsibilities Work Together in the Flip

In Switch 0.31+, room roles (`define_role`, `assume_role`, `release_role`) are assumable instruction bundles backed by a live agent session lease—human participants cannot call `assume_role`. ScopeKeeper pairs Switch's agent-only `@client-desk` room role in `acme-client` with verified human governance roles (`@account-manager` held by Priya and `@delivery-lead` held by Ravi) mapped in `config/rooms.yaml`. At 7:00 PM IST, Clerk sends `MODE autopilot` to `@acme-scout` in `acme-intake`; Scout calls `assume_role(role="client-desk")` in `acme-client` and greets Sam, while Clerk verifies via `get_role_detail` that `held_by` lists `acme-scout`. At 9:30 AM IST, Clerk posts the morning brief, sends `MODE copilot` so Scout calls `release_role()` in `acme-client`, and verifies that `held_by` is empty, returning daytime desk authority to Priya. Whenever a human issues `@clerk confirm`, `@clerk approve`, or `@clerk price` in `acme-delivery` or a change room, Clerk checks the sender's Switch participant identity against `config/rooms.yaml` before executing the state transition.

## 5. Fallbacks for Offline Demos, Missing Room Creation, and Agent Timeouts

Every external boundary sits behind a Port interface (`SwitchPort`, `LLMPort`, `GitHostPort`, `PreviewPort`, `ClockPort`) with both production and deterministic offline adapters:
- **Built-in Scout Fallback (`SCOUT_MODE=builtin`):** If the OpenCode Console agent is offline or fails to assume `@client-desk` within 30 seconds after retry, `services/scout_builtin.py` can act as the second custom agent identity in `acme-client` and `acme-intake` without importing any database or pricing modules.
- **Change Room Pool Fallback:** If a bridged chat platform restricts dynamic channel creation (`can_create_channels == false`), Clerk falls back to claiming the next free room from a pre-created pool (`acme-cr-001` through `acme-cr-010`).
- **Estimator & Builder Fallbacks:** If the Estimator does not reply within 10 minutes, Clerk sends a reminder; at 30 minutes, Clerk computes a heuristic estimate from past merge `Effort-Hours:` trailers marked `low` confidence (forcing human confirmation). For the Builder, Clerk both listens for `@clerk DONE <work_id> pr=<url>` and polls `GitHostPort` so a missed chat message never stalls delivery.

## 6. Protocol Notes & Reconciliations with `sandbox-quantum/switch`

- **`POST /agents/{agent_id}/connection/placements` Payload Shape:** In `core/switch_core/bridges/agent/api/schemas.py` (`ConnectionPlacementsRequest`), `placements` is typed as `dict[str, str]` (`{session_id: room_id}`), whereas `BUILD_PROMPT.md` section 8.3 illustrates a list of `{session_id, room_id}` objects. Following Rule 8 ("The docs win conflicts"), `SwitchProtocolAdapter` supports the canonical `dict[str, str]` schema and automatically falls back to the list schema or `connect_to_room` if an older server revision rejects the dictionary format.
- **`get_role_detail` `held_by` Entries:** In `core/switch_core/bridges/agent/operations/definitions.py`, `get_role_detail` returns `held_by` as a list of holder dicts `[{"name": "acme-scout", "present_here": true, "session_room": "..."}]`. Our adapter normalizes `held_by` entries whether they are dicts (`entry["name"]`) or bare strings (`"acme-scout"`), ensuring compatibility with both Switch 0.31 fixtures and live servers.
